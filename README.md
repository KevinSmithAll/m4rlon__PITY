## 🧠 О проекте

**M4RLON PITY** — настольный мессенджер на Python, построенный на основе клиент-серверной архитектуры и TCP-соединений.

Проект реализует основные механизмы обмена сообщениями: подключение пользователей, регистрацию в системе, маршрутизацию личных сообщений, отслеживание присутствия пользователей и локальное сохранение истории переписки.

Вместо использования готовой платформы для обмена сообщениями приложение реализует собственную логику взаимодействия между клиентом и сервером.

### 🎯 Цели проекта

- 🖥️ Создать настольное приложение для обмена сообщениями.
- 🌐 Разобраться в принципах сетевого взаимодействия через TCP.
- 🔌 Реализовать обмен структурированными данными между клиентом и сервером.
- 💬 Организовать отправку личных сообщений между пользователями.
- 🟢 Добавить отслеживание подключённых пользователей.
- 💾 Реализовать локальное хранение истории переписки.
- 🧩 На практике изучить многопоточность и архитектуру сетевых приложений.

> 💡 **Главная идея:** не просто использовать готовый мессенджер, а разобраться, как устроен собственный.

## 🏗️ Архитектура проекта

Приложение построено по классической клиент-серверной модели.

```text
                 M4RLON PITY
             Сетевой мессенджер

       ┌──────────────────────────┐
       │         КЛИЕНТ A         │
       │                          │
       │  Графический интерфейс   │
       │  Список контактов        │
       │  Окно переписки          │
       │  История сообщений       │
       └────────────┬─────────────┘
                    │
                    │ TCP + JSON
                    ▼
       ┌──────────────────────────┐
       │          СЕРВЕР          │
       │                          │
       │  Управление подключениями│
       │  Регистрация пользователей│
       │  Статусы присутствия     │
       │  Маршрутизация сообщений │
       └────────────┬─────────────┘
                    │
                    │ TCP + JSON
                    ▼
       ┌──────────────────────────┐
       │         КЛИЕНТ B         │
       │                          │
       │  Графический интерфейс   │
       │  Список контактов        │
       │  Окно переписки          │
       │  История сообщений       │
       └──────────────────────────┘
```

### 🔄 Как работает обмен сообщениями

1. Клиент устанавливает TCP-соединение с сервером.
2. Клиент отправляет сообщение регистрации со своим именем.
3. Сервер регистрирует подключение и обновляет список активных пользователей.
4. Клиент получает информацию о контактах и статусах пользователей.
5. Отправитель формирует сообщение с указанием получателя.
6. Сервер находит подключение адресата и пересылает ему сообщение.
7. Получатель отображает сообщение в интерфейсе и сохраняет его локально.

Сервер отвечает за передачу сообщений между подключёнными пользователями, а история переписки хранится на стороне клиента.

## 🚀 Установка и запуск

### 📋 Требования

Для запуска проекта понадобятся:

- Python 3.10 или новее.
- Git.
- Терминал или командная строка.
- Tkinter для графического интерфейса.

### 1. Клонирование репозитория

Открой терминал и выполни:

```bash
git clone https://github.com/KevinSmithAll/m4rlon__PITY.git

cd m4rlon__PITY
```

### 2. Создание виртуального окружения

**Windows — PowerShell**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**Linux / macOS**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Виртуальное окружение позволит изолировать зависимости проекта от остальных Python-приложений.

### 3. Установка дополнительных зависимостей

Для дополнительного оформления графического интерфейса можно установить `ttkbootstrap`:

```bash
python -m pip install ttkbootstrap
```

Основные сетевые компоненты используют стандартную библиотеку Python. Убедись, что Tkinter доступен в твоей среде.

### 4. Запуск сервера

В первом терминале выполни:

```bash
python server.py
```

По умолчанию сервер использует порт `5050`.

Пример сообщения при успешном запуске:

```text
Server listening on 0.0.0.0:5050
```

Не закрывай терминал, пока сервер должен принимать подключения.

### 5. Запуск клиента

Открой второй терминал в каталоге проекта:

```bash
python client.py
```

В окне приложения:

1. Укажи имя пользователя.
2. Введи IP-адрес сервера.
3. Укажи порт `5050`.
4. Подключись к серверу.
5. Выбери контакт и начни переписку.

### 6. Проверка работы

Чтобы проверить обмен сообщениями на одном компьютере:

1. Запусти сервер.
2. Открой клиентское приложение дважды.
3. Подключи оба клиента к адресу `127.0.0.1` и порту `5050`.
4. Используй разные имена пользователей.
5. Отправь сообщение из одного клиента в другой.

Для подключения с другого компьютера используй сетевой IP-адрес машины, на которой работает сервер. При необходимости настрой правила межсетевого экрана.

## 📡 Протокол обмена данными

Клиент и сервер обмениваются структурированными сообщениями в формате JSON поверх TCP.

TCP представляет собой поток байтов, поэтому границы отдельных сообщений не гарантируются. Для разделения сообщений используется заголовок длины пакета.

### Формат пакета

```text
┌────────────────────────┬────────────────────────────┐
│ Заголовок: 4 байта     │ Полезная нагрузка          │
│ Длина сообщения        │ JSON в кодировке UTF-8     │
│ Беззнаковое число      │ Переменная длина           │
│ в сетевом порядке байт │                            │
└────────────────────────┴────────────────────────────┘
```

Для кодирования длины используется формат `!I` модуля `struct`.

### Пример сообщения регистрации

```json
{
  "type": "hello",
  "name": "Alice"
}
```

В этом примере клиент сообщает серверу своё имя.

### Типы сообщений

| Тип | Назначение |
|:--|:--|
| `hello` | Регистрация клиента |
| `contacts` | Передача списка контактов и подключённых пользователей |
| `presence` | Обновление статуса подключения |
| `ping` | Служебное сообщение для проверки активности |
| `error` | Передача информации об ошибке |
| Сообщения личной переписки | Передача сообщений выбранному адресату |

Конкретные поля каждого сообщения определяются обработчиками на стороне клиента и сервера.

### Зачем нужен заголовок длины?

- TCP может передавать одно сообщение несколькими частями.
- Несколько сообщений могут поступить в рамках одного потока данных.
- Заголовок сообщает получателю, сколько байтов нужно прочитать.
- Получатель может собрать полный пакет до декодирования JSON.

Для реализации этого механизма используются функции `send_packet()`, `recv_exact()` и `recv_packet()`.

## 💾 Хранение данных

В проекте разделены серверный список контактов и локальная история переписки пользователей.

### Список контактов

Файл `contacts.json` предназначен для хранения списка контактов.

Пример структуры:

```json
{
  "contacts": [
    "Alice",
    "Bob"
  ]
}
```

Сервер загружает список при запуске и сохраняет изменения при обновлении контактов.

### История переписки

Сообщения клиента хранятся в каталоге `chat_history/` в формате JSON Lines.

Пример структуры каталогов:

```text
chat_history/
└── Alice/
    ├── dm_Bob.jsonl
    └── dm_Charlie.jsonl
```

Пример отдельной записи:

```json
{
  "ts": 1700000000.123,
  "sender": "Alice",
  "text": "Привет, мир!"
}
```

Каждая строка содержит отдельное сообщение. Благодаря этому новые записи можно добавлять в конец файла без полного переписывания истории.

**Важно:** история хранится локально на клиенте и автоматически не синхронизируется между устройствами.

## 🔐 Безопасность

M4RLON PITY — проект для изучения сетевого программирования, а не готовый защищённый мессенджер.

Перед использованием в недоверенной сети необходимо учитывать следующие ограничения:

- **Шифрование.** Обычное TCP-соединение не шифрует содержимое сообщений. Для защиты передачи данных следует добавить TLS.
- **Аутентификация.** Имя пользователя само по себе не подтверждает личность владельца аккаунта.
- **Проверка данных.** Необходимо проверять длину пакетов, структуру JSON и содержимое сообщений.
- **Ограничение нагрузки.** Стоит ограничить размер сообщений, частоту запросов и количество подключений.
- **Защита сервера.** Не следует открывать сервер в публичный интернет без необходимых мер защиты.
- **Локальная конфиденциальность.** Файлы истории содержат читаемый текст и должны быть защищены от постороннего доступа.

Не используй проект для передачи чувствительных данных, пока соответствующие механизмы защиты не реализованы и не проверены.

## 🧪 Решение возможных проблем

| Проблема | Что проверить |
|:--|:--|
| Не удаётся подключиться к серверу | Запущен ли сервер и правильно ли указан порт |
| Сервер недоступен с другого компьютера | IP-адрес, сетевой маршрут и настройки межсетевого экрана |
| Не открывается интерфейс | Установлен ли Python и доступен ли Tkinter |
| Не применяется оформление | Установлен ли `ttkbootstrap` |
| Сообщения не доходят | Подключения клиентов, имена пользователей и сообщения сервера |
| Не отображается история | Рабочий каталог и файлы в `chat_history/` |
| Порт уже занят | Освободи порт или согласованно измени настройки сервера и клиентов |
